## 4. 가격 조정 비율 적용 가능성

질문별 결론:
1. **FDR과 네이버의 조정 방식이 같은가**: FDR(fchart)·네이버 일봉 차트 API·네이버 분봉은 같은 수정주가 체계다. m.stock 일별 시세만 실제 가격이다 **[원천]**.
2. **조정 비율이 OHLC에 적용되는가**: 그렇다. 조정이 있는 4종목 165행에서 시가·고가·저가가 모두 `실제 x (FDR 종가 ÷ 실제 종가)`와 같다. 최대 차이는 1.35원이고 원 단위 반올림 때문이다 **[표본]**.
   - 이벤트 경계에서 비율이 바뀐다. 207940은 10-01까지 0.9923, 10-02부터 1.0이다. 498400은 분배락마다 바뀐다(0.9536 → 0.9676 → 0.9830 → 1.0).
3. **조정 종가와 비조정 OHLC가 한 행에 섞이는가**: 섞이지 않는다. 저장 시가·고가·저가·거래량은 FDR 값(조정)이다. 저장 종가는 공식 종가 x 같은 비율이다. 같은 체계지만 **세션 범위는 섞인다**(2절).
   - 예외는 event_boundary 행(207940 10-01)이다. 종가도 원천 값(애프터마켓 종가)이다.
4. **애프터마켓을 뺀 시가·고가·저가를 구할 수 있는가**: 최근 7거래일만 가능하다(분봉). 분봉이 이미 수정주가 체계라 비율을 따로 곱할 필요가 없다.
   - 그보다 오래된 날은 원천이 없다. **비율로 복원할 수 없다**: 정규장 고가·저가는 하루 고가·저가와 다른 값이고, 비율은 체계를 바꿀 뿐 세션을 나누지 않는다.
5. **정규장 거래량과 전체 거래량을 구분할 수 있는가**: 7거래일만 가능하다(분봉 09:00~15:30 합계). 공식 정규장 거래량과는 대조하지 못했다 **[미확인]**.
   - **거래량은 가격 비율의 역수로 조정된다**: 165/165행에서 FDR 거래량 = 실제 거래량 ÷ 비율(±0.02%) **[표본]**. 가격 비율을 거래량에 곱하면 틀린 방향이다. 이번 작업은 거래량에 어떤 비율도 적용하지 않았다.
- 남는 위험(44차와 같음): 다음 분배락·기업 이벤트 때 FDR이 과거 전체를 다시 조정한다. 재수집 창 밖의 저장 행은 이전 체계로 남는다. 종가뿐 아니라 시가·고가·저가·거래량도 같다.

## 5. 거래량 집계 기준

- 저장 거래량 = KRX 하루 전체다. 포함하는 것은 정규장, 장후 종가매매, 애프터마켓, 분봉에 없는 체결이다. NXT는 포함하지 않는다(2절).
- "분봉에 없는 체결"은 주식 105/1,800행, ETF 236/300행에서 나왔다. 069500 11-12는 838,420주(3.9%)였다. 대량매매 등으로 보이지만 구성은 **[미확인]**이다.
- 정규장 거래량은 분봉이 있는 최근 7거래일만 계산할 수 있다(`app/session_ohlcv.py`). 저장은 하지 않았다(11절 제안).

1. **원천**: FDR `KrxIndexReaderCache`(`raw.githubusercontent.com/FinanceData/fdr_krx_data_cache/master/data/index/year_ks11/{연도}.csv`, 제3자 저장소)다. 열은 Close·Open·High·Low·Volume·Amount·MarCap 등이다. 저장은 종가·등락률만 한다 **[원천]**.

3. **장중 값이 남는 행은 마지막 행 하나뿐이다** **[원천: 커밋 9개 파일 대조]**.

   - 11-12 14:43 5,305.47 → 23:01 5,342.73
   - 코스닥도 같다: 11-12 14:43 688.45 → 23:01 696.53
   - 앞선 날짜는 커밋마다 같다.

## 8. 현재 구현의 문제점(수정 전, 7283a5a)

1. 지수 수집기가 캐시 행을 시각과 관계없이 저장했다. 11-13 14:59에 `--dry-run`으로 확인했다.
   - 수정 전: KS11·KQ11 각 신규 1건(11-13 장중 값 5,315.45 / 708.22)을 저장하려 했다.
   - 수정 후: 둘 다 `intraday`로 보류했다(네이버 현재값 5,284.85 / 700.52).
   - 장 마감 뒤 15:41에 다시 실행: 캐시는 여전히 14:00 커밋(코스피 5,315.45, 코스닥 708.22)이었다. 네이버는 `marketStatus` CLOSE로 확정값(5,290.53 / 699.66)을 보였다. 수정 코드는 두 행을 `mismatch`로 보류했다. 수정 전 코드라면 장중 값이 "11-13 종가"로 저장되고 시장 요약에 `latest`로 보였을 상황이다 **[원천]**.
   - 같은 시각 오늘 행은 원천마다 달랐다. 삼성전자 거래량: fchart(KRX) 12,309,990 / m.stock(통합) 19,444,040 / 실시간 NXT 7,139,482(`AFTER_MARKET` 세션). 펩트론 저가: fchart 92,100 / m.stock 92,000(NXT 체결). 저장 수집기는 주식 오늘 행을 쓰지 않으므로 영향은 없다.
2. 15:30 뒤 시장 요약은 오늘 행을 쓴다. 장중 행이 저장돼 있으면 장중 값이 확정 종가처럼 보였다.
3. 저장 행 하나 안에서 시가·종가는 정규장, 고가·저가·거래량은 하루 전체인데 이 정의가 응답·답변 어디에도 없었다.
4. 하루 시세 답이 고가·저가를 말할 때 애프터마켓 체결일 수 있다는 사실을 밝히지 않았다(펩트론 10-07 저가 91,500).
5. 전망의 거래량 배수 설명에 거래량 집계 기준이 없었다.

## 12. 프런트엔드에서 참고할 데이터 표시 정책(제안, API 변경 없음)

지금 API로 할 수 있는 것:
1. **지수**: `GET /api/market/overview`의 `indices[].date`를 값 옆에 "MM-DD 종가"로 표시한다. `lag_business_days > 0`이면 지연 배지를 단다(브리핑 화면은 이미 그렇다). 시장 카드(`MarketSummaryCard`)는 지금 지수별 기준일을 보이지 않는다.
2. **15:40~23시**: 지수가 전 거래일로 보이는 것은 정상이다(확정 전 보류). "장 마감 지수는 확정 뒤 반영" 같은 안내를 지연 배지 툴팁에 쓸 수 있다.
3. **차트 툴팁**: 주식·2026-09-14 이후 날짜면 "시·고·저" 옆에 "고·저는 장 마감 뒤 애프터마켓 포함"을 표시한다. ETF는 붙이지 않는다. 종가 선은 정규장 공식 종가다.
4. **거래량 막대·급증 목록**: "KRX 하루 거래량(애프터마켓 포함, NXT 제외)"로 표기한다. "정규장 거래량"이라고 쓰지 않는다.
5. **값이 없을 때**: 지수 `close`가 null이면 "—"를 보인다(0으로 그리지 않는다). 지금 카드는 이미 그렇다.

API 변경 제안(합의 전 구현하지 않음):
- `price-history` 응답에 `price_basis` 객체 추가(선택 필드, 기존 필드 불변). 예: `{"open": "regular", "close": "official_regular_close", "high_low": "krx_full_day", "volume": "krx_full_day_excl_nxt", "after_market_from": "2026-09-14", "adjusted": "source_adjusted"}`.
- `market/overview`의 `indices[]`에 `confirmation_pending: bool` 추가. 오늘 행을 확정 대기로 보류 중이면 true다. 화면이 지연 사유를 "수집 실패"와 구분할 수 있다.
- C 승인 뒤 `price-history` items에 `regular`(정규장 OHLCV, 있는 날만) 추가.
