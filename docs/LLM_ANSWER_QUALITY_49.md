## 2. 뉴스 기사 과거 가격과 현재 주가 분리(최우선)

수정 전(48차 holdout D4 실답): "## 주가 동향 … 30일 KRX 마감 기준, LG전자 주가가 147,800원으로 거래를 마쳤다 …" 뒤에 "데이터 기준일: 2026-11-12"가 붙었다.
- 숫자 검증은 기사 본문에 있는 값이라 통과시켰다.
- 날짜 없는 기사 시세 규칙은 "30일"을 날짜로 보고 통과시켰다.

원칙(주식·ETF 같음, `app/answer_guard.strip_article_prices`):
1. 현재 주가·등락률·계산값은 DB 시세(도구 결과의 구조화 값)만 쓴다. "주가 동향" 절에서는 기사에서만 나온 시세형 숫자를 지운다.
2. 기사 시세를 다른 절에서 쓰려면 같은 문장에 그 기사의 **발행일**이 있어야 한다(ISO·점·"M월 D일"). "30일"처럼 일만 쓰거나 다른 날짜면 지운다.
3. 발행일이 없는 기사의 시세형 숫자는 어디에도 쓰지 않는다.
4. "주가 동향"이 비면 DB 시세 요약 문장(`stock_tool` summary)으로 채운다. 현재 시세는 DB 값과 같다.
5. 실적·매출·영업이익·수주 금액(억·조 단위, 실적 낱말 문맥의 %)은 시세가 아니라서 그대로 둔다.
   - 시세형 숫자: 원·%, 1억 미만, 시세 낱말이 있거나 실적 낱말이 없는 문장.
   - DB 값과 맞는지는 표기 자리수로 반올림해 본다("16만원대"는 DB 152,300원과 같은 값이 아니다).
6. 기사 제목을 그대로 인용한 줄은 출처 표시로 보고 건드리지 않는다. 출처(`sources`)와 기사 연결은 바뀌지 않는다.

LLM 입력 단계(`app/etf.news_result_for_llm(result, etf=False)`, 주식):
- 시세 낱말이 있고 실적 낱말이 없는 기사 문장의 원·% 숫자에 발행일을 붙인다("146,900원[기사 2026-10-30 시점]").
- 발행일이 없으면 그 숫자를 가린다.
- 답에 남은 표시는 "(2026-10-30 기사 기준)"으로 바뀐다. ETF는 기존대로 모든 숫자를 가린다. 원본 도구 결과·기록·출처는 바꾸지 않는다.

테스트 `tests/test_news_price_separation_49.py`(18개, 48차 D4 원문 기반):
- 현재 절 제거와 DB 요약 채움, 실적 수치 보존.
- 발행일을 밝힌 과거 가격 유지, "30일"·다른 날짜·발행일 없는 기사는 제거.

## 3. 다국어 기간·전망 판정

### 3.1 한국어 기반부터 고쳤다(정규화가 옮겨 갈 표현이 먼저 맞아야 한다)
수정 전 한국어도 틀렸다.
- "최근 5거래일"은 기간으로 읽히지 않았다(`parse_period` None → LLM이 추측).
- "향후 20거래일 전망"은 기본 1주일(5거래일)로 답했다(숫자가 바뀜).
- "향후 1년 전망"도 말없이 1주일로 답했다.

수정:
- `period_parser`: "최근 N거래일/영업일"은 정확히 N거래일이다. "향후·앞으로·다음 N거래일", "N거래일 뒤", "날짜 이후 N거래일"은 과거 창이 아니다.
- `outlook.horizon_in`: 숫자로 말한 미래 기간을 거래일로 환산한다.
  - 5·20·60거래일(1주·1개월·3개월)이면 그 기간이다.
  - 그 밖 90거래일 이하이면 가장 가까운 지원 기간으로 분석하고, 답 맨 앞 한 문단에 밝힌다("요청하신 기간(…, 약 10거래일)은 … 가장 가까운 향후 5거래일(1주일) 기준으로 분석했습니다.").
  - 90거래일 초과·"내년"·"향후 1년"은 전망을 하지 않고 지원 기간을 안내한다. 도구 호출이 없다.
  - 안내 문단과 안내 답은 en/ja/zh 고정 문장으로 옮긴다(`answer_i18n`).
- `agent._price_window`(1차 공식 평가에서 찾아 고침): "최근 20거래일" 비교가 오늘까지의 날짜 창이었다. 오늘 종가가 아직 없으면 19거래일만 비교했다(신규 문항 C01~C03).
  거래일 수로 말한 기간은 이제 저장된 최근 N개 거래일(장중 행 제외)이 창이다.

### 3.2 영어·일본어·중국어 → 한국어 표준 표현(`app/intent_i18n.py`)
낱말 치환 사전이 아니라 (방향, 수, 단위)를 읽어 다시 쓴다.
- 과거 창: "over the last 5 trading days" / "直近5営業日" / "最近5个交易日" → "최근 5거래일"
- 미래 창: "over the next 5 trading days" / "今後5営業日" / "未来5个交易日" → "향후 5거래일"
- 상대 시점: last/next week·month, 先月/来月, 上个月/下个月 → 지난주·다음 달 …
- 이동평균·수익률 창: "5-day and 20-day moving averages" / "5日・20日移動平均" / "5日和20日均线" → "5일·20일 이동평균"
- 의도: 전망·오를까/떨어질까·사도 될까·분석·비교·주가·거래량·뉴스·공시·추이를 끝에 덧붙인다.
- 종목명은 등록명으로 바꾼다. 그래서 LLM 도구 인자도 등록명이 된다.
- 한글이 종목명 밖에 있으면(한국어 질문) 한 글자도 바꾸지 않는다.
- 판정·LLM 입력에만 쓰고, 리포트에는 원래 질문을 저장한다. 내부 meta에 `question_routed`·`routing_steps`를 남긴다(API에는 안 나감).
- 모호한 이름("Samsung", "三星", "現代")은 그대로 둔다. 기존 "종목을 되묻는 안내"로 간다.

테스트 `tests/test_intent_i18n_49.py`(67개, 6.2의 재확인 수정 포함):
- 같은 N의 과거·미래 질문이 다른 경로로 가는지(언어 3 × N 2).
- 상대 기간, 지원 밖 기간, 이동평균 창, 비교 종목·창, 한국어 미변경, 모호 이름.
- ETF 구성종목 표현 유지, 원래 질문 저장, 안내 번역, N거래일 창.

4. 줄 단위 재시도는 줄 앞 마크다운 표식(글머리표·번호·제목)을 떼고 내용만 "한 줄" 지시와 함께 보낸 뒤 표식을 다시 붙인다.
5. 섹션 제목(48차 코드 사전)과 표·목록 형식은 코드가 처리한다. 자리표시자·숫자·한글·문자 검증은 모두 그대로다.

## 8. 해결하지 못한 문제
1. **N4형 번역 실패**: LLM이 만든 한국어 문장 자체에 영어가 섞이면("downwards trend를") 번역 검증을 통과하지 못하고 데이터 요약이 된다(안전). 한국어 답 단계에서 섞인 언어 문장을 다루는 것은 별도 작업이다.
2. **번역 fallback 0건은 아니다**(57문항 4, 신규 3). LLM이 쓴 긴 문단의 자리표시자 누락·되돌림이 남은 원인이다.
3. **비교 질문의 LLM 경로**(L01): "주가와 거래량 비교"처럼 코드 비교 경로가 받지 않는 질문은 LLM 경로다. 드물게 종목을 못 찾는다(안전한 거절). 재현되지 않았다.
4. **기사 시세 판정은 숫자 단위(원·%) 기반**이다.
   - "3만원대 이탈" 같은 대략적 표현이 DB 가격대와 맞으면 남는다(뉴스 절, 경계 사례).
   - 한글 수사("19만2,600원")를 판정기가 일부만 읽는 한계가 있다.
5. **일본어·중국어 종목명**은 공식 출처가 없어 86종목에 머문다. 운용사·IR 자료 같은 확인 가능한 출처를 정하면 늘릴 수 있다.
6. **지원 밖 표현**: "in the second half of next year", "过去半年" 같은 표현은 정규화하지 않는다. 기존 판정(대개 LLM 경로)으로 가고, 전망 기간이 범위를 넘으면 안내한다.
7. **신규 문항의 1개월 기대값 오류**(19~23)는 고정 원칙상 그대로 두었다. 다음 세트부터 24(평일 수)로 적는다.

## 10. 프런트엔드 참고(API 계약 변경 없음, 제안 없음)
`backend/API.md` 끝의 49차 절에 같은 내용이 있다.
- "## 주가 동향"에는 DB 시세만 나온다. 기사 시세는 다른 절에서 "(YYYY-MM-DD 기사 기준)" 같은 발행일과 함께만 나온다. 비어 버린 절은 DB 요약 문장으로 채워진다.
- 전망 답 맨 앞에 "요청하신 기간(…)은 지원하는 전망 기간이 아니어서 …" 한 문단이 붙을 수 있다. 90거래일 초과 전망 질문은 `used_tools` 빈 배열의 안내 답이다.
- 영어·일본어·중국어 질문이 한국어 질문과 같은 코드 경로를 탄다. 그래서 `used_tools`가 한국어 질문과 같아지고(예: 전망은 `stock_tool`·`market_tool`), `translation_status`의 `localized`가 늘었다.
- 리포트 목록·상세의 질문은 사용자가 입력한 원문 그대로다.
- "Samsung"·"三星"·"삼성"·"현대"·"롯데"처럼 그룹 이름만 있는 질문은 후보 종목을 보여 주며 되묻는 답이다(`used_tools` 빈 배열). 예전에는 모델이 대개 삼성전자 등을 임의로 골랐다.
