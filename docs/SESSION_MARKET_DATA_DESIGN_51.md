### 3.3 권고 스키마(안 D)

```text

  id               BIGINT PK
  company_id       INTEGER NOT NULL  FK company(id) ON DELETE CASCADE
  price_date       DATE NOT NULL                 -- KRX 거래일(KST)
  session          VARCHAR(16) NOT NULL          -- 'regular' | 'closing_price' | 'after_market' (CHECK)
  open_price       NUMERIC(14,4) NOT NULL        -- 수정주가 분봉이 소수라 stock_price(12,2)보다 넓게
  high_price       NUMERIC(14,4) NOT NULL
  low_price        NUMERIC(14,4) NOT NULL
  close_price      NUMERIC(14,4) NOT NULL
  volume           BIGINT NOT NULL               -- 그 세션 분봉 거래량 합계(주)
  bar_count        SMALLINT NOT NULL
  first_bar        CHAR(4) NOT NULL              -- HHMM
  last_bar         CHAR(4) NOT NULL
  close_auction_bar CHAR(4)                      -- regular만: 종가 단일가 봉 시각('1530' | '1532' …), 없으면 NULL
  status           VARCHAR(24) NOT NULL          -- 'ok' | 'late_close_auction' | 'no_close_auction_trade' (CHECK)
  source           VARCHAR(24) NOT NULL          -- 'naver_minute'
  price_basis_date DATE NOT NULL                 -- 이 값이 어느 날 기준의 수정주가 체계인가(= 수집일)
  collected_at     TIMESTAMPTZ NOT NULL
  created_at       TIMESTAMPTZ NOT NULL DEFAULT now()

  INDEX (price_date)                             -- 날짜별 수집 확인·health 검사용
```

| 항목 | 판단 |
| --- | --- |
| 종목코드 | `company_id`(기존 테이블과 같은 방식). ticker는 JOIN으로 얻는다 |

### 3.4 거래 세션 구분(확인된 범위만)

| 세션 값 | 정의(분봉 시각) | 근거 | 확인 수준 |
| --- | --- | --- | --- |
| `regular` | 09:00 ~ 종가 단일가 봉. 종가 단일가 봉은 15:30 봉이다. 15:30 봉이 없고 15:31~15:39 봉이 있으면 그 첫 봉이다(관찰값 15:32) | 15:30 봉 종가 = 공식 종가(1,765/1,765), 15:32 봉 종가 = 공식 종가(35/35) | [표본] |
| `closing_price` | 위 봉 다음 ~ 15:59(관찰 15:40~15:59) | 봉의 시가·고가·저가·종가가 모두 그날 15:30 봉 종가와 같다(스냅샷 11-06~11-13, 15:30 봉이 있는 날 5,686/5,686봉) | [표본] |
| `after_market` | 16:00 ~ 19:59(관찰) | KRX 분봉에 있고 하루 합계가 KRX 일봉 거래량과 같다 | [표본] |
| (저장하지 않음) NXT | — | 원천에 없다. 분류할 데이터가 없다 | [미확인] |
| (저장하지 않음) 분봉에 없는 체결 | KRX 일봉 거래량 − 분봉 합계 | 주식 105/1,800행, ETF 236/300행에서 생긴다. 장전 시간외·대량매매로 추정 | [미확인] |

- 요청서의 "NXT 애프터마켓"은 이 원천의 16:00~20:00 봉과 다르다. 이 봉들은 KRX 체결로 판정됐다(50차). 그래서 세션 이름을 `after_market`(KRX)으로 두었다. NXT 세션은 원천이 생길 때까지 만들지 않는다.
- "확인 불가능한 데이터"는 행으로 저장하지 않는다. 분봉에 없는 거래량은 `stock_price.volume`(다른 원천·다른 조정 체계)과 빼야 나오는 값이라, 저장하면 두 원천이 한 행에 섞인다. 필요할 때 health·품질 검사에서 계산해 경고로 보인다.
- ETF는 애프터마켓 봉이 없다. 그래서 `regular`와 `closing_price` 행만 생긴다. 종가 단일가 체결이 없는 날은 `regular.status = 'no_close_auction_trade'`, `close_auction_bar = NULL`이다.
- 지금 `app/session_ohlcv.py`의 `SESSIONS`(regular 0900~1530 고정)는 15:32 봉을 `closing_price`로 센다. 저장을 구현하기 전에 위 규칙으로 바꿔야 한다. 이번에는 바꾸지 않았다. 감사 스크립트 결과에는 영향이 없다(1.5절).

### 3.5 기존 `stock_price`와의 역할 분리·중복

- `stock_price`는 그대로 "서비스 기준 일봉"이다. 종가 = 공식 종가, 나머지 = KRX 하루 값이다. 모든 기존 기능은 이 테이블을 계속 쓴다. 그 행은 바꾸지 않는다(UPDATE·DELETE 없음).
- `stock_price_session`은 "세션별 원천 기록"이다. 쓰는 곳은 감사, 차트의 정규장 표시(합의 시), 정규장 거래량 신호(20거래일 뒤, 옵션)다.
- 중복: 정규장 시가와 종가는 `stock_price`의 시가·종가와 같은 값(조정 비율 차이만)이다. 일부러 중복을 둔다.
  - 두 테이블 값이 일치하는지가 곧 품질 검사다: `regular.open x factor = stock_price.open`, `regular.close x factor = stock_price.close`.
  - 정규화로 없애면 이 검사를 할 수 없다.

### 3.6 수정주가·기업 이벤트

- 분봉은 **수집 시점의 수정주가 체계**다. 그날 저녁에 받으면 그 뒤 이벤트가 아직 없으므로 실제 가격이다. `price_basis_date = price_date`다.
- 이벤트(분배락·액면분할 등) 뒤에도 이 테이블의 행은 다시 쓰지 않는다. insert-only다. 원천이 과거 분봉을 다시 계산해도 7거래일 밖은 다시 받을 수 없어서, 다시 쓰는 정책은 일부 행만 바꿔 체계를 섞는다.
- `stock_price`와 비교하거나 기간 신호를 계산할 때는 **날마다의 조정 계수**를 쓴다: `factor(d) = stock_price.close_price(d) / regular.close_price(d)`.
  - 조정 가격 = 세션 가격 x factor, 조정 거래량 = 세션 거래량 ÷ factor다. 50차에서 거래량은 가격 비율의 역수로 조정됨을 확인했다(165/165행).
  - 같은 날 안의 비율(정규장 거래량 ÷ 하루 거래량, 정규장 고가 vs 하루 고가)은 체계와 관계없이 계산할 수 있다.
- 남는 위험: `stock_price` 자체가 재수집 창 밖에서 이전 체계로 남는 문제(44차)는 그대로다. factor는 `stock_price`가 현재 체계일 때만 맞다.
  - 46차 `event_boundary` 행처럼 종가가 원천 값인 날은 factor가 틀린다. 그런 날은 계산에서 제외하고 경고로 보인다.

### 3.7 거래량 집계 기준

- 각 세션 `volume` = 그 세션에 속한 분봉 거래량 합계다(수집 시점 체계). 정규장에는 종가 단일가 봉이 들어간다.
- 세 세션 합계 = 분봉 합계이고, **KRX 일봉 거래량보다 작거나 같다**(분봉에 없는 체결 때문).
- 이름은 "정규장 거래량(분봉 합계)"로 쓴다. KRX 공식 정규장 거래량과 대조하지 못했으므로 "공식 정규장 거래량"이라고 부르지 않는다 **[미확인]**.

### 3.11 Alembic 마이그레이션·health·CI 영향

- 새 리비전 하나로 `c7e2a9f4d158` 뒤에 테이블과 인덱스를 추가한다. 기존 테이블은 바꾸지 않는다.

- **CI**: `backend-integration`·평가 job은 빈 DB에 `alembic upgrade head`를 돌린다. 새 테이블은 자동으로 생긴다. 시드(`scripts/ci_seed.py`)는 바뀌지 않는다.
- **데이터 품질 검사**: `refresh_data --status`에 새 검사를 넣는다.
  - 세션 수집 지연
  - `regular.open/close` vs `stock_price` 불일치(factor 반영)
  - 하루 고가 ≠ 세션 고가 최댓값
  - 같은 날 `regular` 행이 없는 종목 수
- 적용 순서(승인 뒤):
  1. 개발 DB 백업(`pg_dump`, 기존 절차)
  2. 개발 DB에 `alembic upgrade head`
  3. 코드 배포
  4. 보존 파일로 11-05~ 백필(insert-only, `ON CONFLICT DO NOTHING`)
  5. 백필 결과를 50차 감사와 대조(시가·종가 일치 수 등)
  6. `refresh_data`에 `session` 단계를 켠다(20:10 뒤 또는 다음 날 오전 실행)

### 5.3 API 필드 명세(제안, 합의 전 구현하지 않음)

#### `price-history.price_basis`

| 항목 | 값 |
| --- | --- |
| 위치 | `GET /api/stocks/{ticker}/price-history` 응답 최상위(`items`와 같은 수준). 항목마다 넣지 않는다(응답 크기) |
| 타입 | 객체(아래 키 모두 문자열 또는 null) |
| 필수 여부 | 서버는 항상 넣는다. 프런트는 **선택 필드로 취급**한다(이전 서버·캐시 응답 호환) |
| 기존 응답 호환 | 기존 필드는 그대로다. 프런트 스키마가 strict가 아니라 무시해도 깨지지 않는다 |

| 키 | 타입 | 값 | 의미 |
| --- | --- | --- | --- |
| `version` | int | `1` | 정의가 바뀌면 올린다 |
| `close` | string | `"official_regular_close"` | 공식 종가(정규장 15:30) x 원천 수정주가 비율 |
| `open` | string | `"krx_regular_open"` | KRX 정규장 시가 |
| `high_low` | string | 주식 `"krx_full_day"` / ETF `"krx_regular"` | 하루 범위(애프터마켓 포함) / 정규장 |
| `volume` | string | `"krx_full_day_excl_nxt"` | KRX 하루 거래량, NXT 제외 |
| `after_market_from` | string(date) \| null | 주식 `"2026-09-14"`, ETF `null` | 이 날짜 이상인 행의 고가·저가·거래량에 애프터마켓이 들어 있다 |
| `before_after_market` | string | `"unverified"` | 09-11 이전 행에 당시 시간외 단일가 체결이 들었는지 확인하지 못함 |
| `adjusted` | string | `"source_adjusted"` | 가격 4개는 같은 비율, 거래량은 역수로 조정 |

50차 보고서 12절 예시와 비교: 키 이름을 `high_low`·`after_market_from`으로 맞췄다. `version`·`before_after_market`을 더했다. 프런트가 툴팁을 날짜별로 정할 수 있게 `after_market_from`을 null 가능 날짜로 정했다.

#### 시장 요약 `indices[].confirmation_pending`

| 항목 | 값 |
| --- | --- |
| 위치 | `GET /api/market/overview`의 `indices[]`, **그리고 일일 브리핑 `content.sections.market.indices[]`**(시장 카드가 읽는 곳) |
| 타입 | boolean |
| 필수 여부 | overview: 항상 넣음(기본 false). 브리핑: 새로 만든 브리핑부터 넣음. 이미 저장된 브리핑에는 없다 → 프런트는 없으면 false로 본다 |
| 의미 | 오늘이 KRX 거래일이고 마감 + 10분이 지났는데, 오늘 지수 행이 확정 검증(`app/index_confirm.py`)에서 보류돼 아직 저장되지 않았다. 이때 `date`·`close`는 전 거래일 확정값이다 |
| false인 경우 | 오늘 행이 저장됨, 장중(아직 마감 전), 휴장일, 또는 마지막 지수 수집이 실패(이때는 `last_collection.index.status = failed`로 구분) |
| 호환 | 선택 필드 추가라 기존 화면에 영향이 없다 |

구현 메모(합의 뒤):
- 보류 결과(`held_dates`)는 지금 어디에도 저장되지 않는다. `data_refresh_log`의 기존 열(`quality_status='warning'`, `error_code='index_confirmation_held'`)에 남기면 마이그레이션 없이 계산할 수 있다.
- 시각 규칙만으로 계산하면 수집 실패와 구분하지 못한다. 그래서 위처럼 기록과 함께 쓴다.
- 브리핑은 불변 스냅샷이다. 16시에 만든 브리핑은 다음 날까지 `confirmation_pending: true`로 남는다. 화면은 "확정 뒤 다시 만들기" 안내를 붙일 수 있다(자동 재생성은 하지 않는다).

#### 세션 테이블 승인 뒤(별도 합의)

- `items[].regular`: `{open, high, low, close, volume}`(정규장, 수집한 날만, 없으면 키 생략)
- 확인할 것: 차트에 정규장 범위를 겹쳐 그릴지, 거래량 막대를 정규장과 장 마감 뒤로 나눠 쌓을지, 정규장 값이 없는 과거 구간을 어떻게 보일지

### 5.4 프런트엔드 담당자에게 묻는 것

1. `price_basis`를 응답 최상위 한 번만 받는 방식으로 충분한가, 항목마다 필요한가
2. `confirmation_pending`을 일일 브리핑 market 영역에도 넣는 데 동의하는가(시장 카드가 그 응답을 읽음)
3. 시장 카드에 지수별 기준일·지연 배지를 넣을 수 있는가(정책 1·5, API 변경 없음)
4. 툴팁·거래량 문구의 네 언어 번역을 프런트 i18n 키로 둘지, 서버가 문구를 줄지
5. 세션 테이블을 승인하면 정규장 값을 화면에 보일 필요가 있는가. 없으면 안 C나 B로 줄일 수 있다(3.2절)

### 6.1 2026-09-14 경계(새로 정리한 위험)

- 20거래일 평균을 쓰는 신호에서, 평균 창이 09-14를 걸치면 애프터마켓이 없던 날과 있던 날이 섞인다. 09-14부터 약 20거래일(10-13경)까지가 그런 창이다.
- 지금(11-14) 계산하는 신호는 창이 모두 09-14 뒤라 기준이 같다.
- 백테스트나 그 구간 사건 반응을 다시 볼 때는 이 섞임을 적어야 한다.

### 6.2 정규장 거래량이 없는 동안의 설명 제안

원칙:
1. 거래량이 들어간 답·화면에는 집계 기준을 한 번 밝힌다. 문구: "거래량은 정규장과 장 마감 뒤 KRX 애프터마켓 체결을 합친 KRX 하루 거래량입니다(NXT 체결 제외)." 50차 `app/price_basis.VOLUME_BASIS_NOTE`와 같은 문구다.
2. 배수(급증·반응)는 "평균도 같은 기준으로 계산해 보통 날은 차이가 작지만, 장 마감 뒤 공시·급변이 있던 날은 배수가 크게 나올 수 있습니다"를 덧붙일 수 있다(급증 목록·사건 반응).
3. **쓰지 않는 표현**: "정규장 거래량", "정규장 기준으로 검증된 거래량", "과거 전체가 정규장 기준".
   - 정규장 분리를 확인한 구간은 2026-11-05~11-13 분봉뿐이다.
   - 09-14~11-04는 원천 정의가 같다고 추정할 뿐이고, 09-11 이전은 **[미확인]**이다.
4. 지금 기준 문구가 없는 경로는 `discovery`·`market_ranking`·`briefing`·`daily_briefing`·`price_flow`·`event_reaction`·`period_answers`의 거래량이다. 다음 차수 후보로 두고 이번에는 코드를 바꾸지 않았다(9절).

## 7. 미해결 데이터 한계

1. KRX·NXT 공식 원천은 여전히 없다. 모든 판정은 네이버 원천 내부 대조다 **[미확인]**.
2. 2026-11-05 이전 정규장 시가·고가·저가·거래량은 구할 수 없다.
3. 분봉 원천의 보관 창 규칙(거래일인지 달력 일수인지)은 **[미확인]**이다. 11-13에는 11-05부터, 11-14(토)에는 11-06부터 줬다.
4. 15:32 종가 단일가 봉의 원인(VI 연장 추정)은 공식 자료로 확인하지 않았다.
5. 분봉에 없는 체결(일봉 − 분봉 합계)의 구성은 **[미확인]**이다.
6. NXT 체결·거래대금은 분봉 원천에 없다.
7. 2026-11-06~11-12의 원천 불변은 하루(11-13 → 11-14) 동안만 확인했다. 기업 이벤트 뒤에는 과거 분봉이 다시 계산될 수 있다.
8. 분배락·기업 이벤트 뒤 `stock_price` 재조정 체계가 섞이는 위험(44차)은 그대로다. 이 때문에 세션 factor 계산도 영향을 받는다(3.6절).
9. 지수 확정 대조에 쓰는 네이버 지수 일별도 비공식 API다(50차와 같음).
