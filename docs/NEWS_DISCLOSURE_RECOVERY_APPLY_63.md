**114,038**
- 4단계의 수다. 날짜·도메인·ETF 이름·중복은 걸렀지만, 관련성 판정 전이다.
- 62차 도구(그리고 기존 `collectors.fetch_and_save_news`)는 관련성 판정을 저장 차단으로 쓰지 않는다.
- 관련성이 낮은 기사도 `is_relevant=false` 표지를 달아 저장한다. 읽는 경로가 모두 `is_relevant.isnot(False)`로 거른다. 대상: `stock_feed`, `briefing_db`, `daily_briefing_db`, `event_reaction_service`, `outlook`, `related_news`, `news_tool`, `rag_search_tool`.

**104,366**
- 114,038 중 `is_relevant`가 False가 아닌 기사다. 3단계(관련성 통과)이자 4단계(신규)인 수다.

**판단**
- 차이 9,672건은 설명할 수 있는 단계별 차이다.
- 다만 요청서 3절 조건("관련성 필터를 통과하지 않은 기사가 INSERT 대상에 포함되면 안 된다")에는 걸린다. 62차 코드 그대로 실행하면 그 9,672건이 INSERT 대상에 들어간다.
- 그래서 **DB 쓰기 전에 코드를 고쳤다**(커밋 `1b3a620`).
  - `news_recovery.store_news(relevant_only=True)`: 관련성이 False인 기사는 저장 전 검증·격리 기록 **전에** 뺀다. 검증이 제목·본문을 바꿔 판정이 달라진 경우를 대비해, 행을 만든 뒤에도 False 행은 한 번 더 뺀다. 판정 함수는 기존 수집과 같은 `is_relevant_news`다.
  - `recover_news_disclosures --relevant-only`: 상태 파일 키에 `relevant_only`를 남긴다(다른 설정의 상태 파일과 섞이지 않는다). 요약·실행 기록 note에 `irrelevant_skipped`를 남긴다.
  - 기본값(옵션 없음)은 기존 동작 그대로다.
  - 함께 고친 것: DART 인증·키 오류(010·011·012·901)가 나면 나머지 종목 요청을 멈춘다(`stopped=dart_auth`). 요청서 6절 "인증 오류" 중단 조건에 맞췄다. 기존 020 중단은 그대로다.
  - 테스트 2개를 추가했다(18절).
- 저장하지 않은 10,128건은 나중에 승인이 나면 옵션 없이 다시 실행해 추가할 수 있다. 기존 (종목, URL)은 건너뛴다. 단, 네이버 검색 범위가 밀리면 일부는 받을 수 없다.
- 반대 방향, 즉 넣은 뒤 지우는 것은 이번에 금지된 DELETE라서 이 방향을 골랐다.

**사후 확인**
- 새로 들어간 112,787행 중 `is_relevant=false`는 0이다.
- 저장된 제목·본문으로 `is_relevant_news`를 다시 돌려도 False 0이다.
