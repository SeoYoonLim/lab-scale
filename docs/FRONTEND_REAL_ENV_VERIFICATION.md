# 프런트엔드 실제 환경 통합 확인 체크리스트

대상: 백엔드 담당과 프런트엔드 담당(서윤). 지금까지 프런트는 **가짜 시세·가짜 뉴스/공시·Ollama 없는 로컬 백엔드**로만 확인했다.
이 문서는 실제 데이터와 실제 LLM이 있는 환경에서 **아직 못 본 것만** 같이 확인하려는 순서다. 확인한 날짜와 결과는 맨 아래 표에 적는다.

## 0. 이미 확인한 것(다시 안 해도 되는 것)

- 문서의 실제 응답 예시 9개로 만든 계약 테스트, 실제 백엔드 통합 테스트 8개(가입·주문·성과·노출·진단·브리핑·기록·계정 복구·탈퇴·
  뉴스/공시/365일 주가), 브라우저로 계정 복구 22개·탈퇴 15개·종목 상세 19개 항목(전부 **가짜 데이터**, Ollama 없음).
- 영어·일본어·중국어 화면 라벨(번역 초안). 모바일 폭 레이아웃.

## 1. 준비(백엔드 쪽)

| 필요한 것 | 방법 | 비고 |
| --- | --- | --- |
| DB | `docker compose up -d` -> `cd backend` -> `alembic upgrade head` | |
| 실제 데이터 | 덤프를 복원하거나 `python -m scripts.refresh_data` | 시세·뉴스·공시·ETF 구성·시장 지수·환율. 네이버/DART 키 필요 |
| LLM | Ollama 실행 + `llama3.1:8b`, `bge-m3` | 없으면 리서치·진단은 "규칙 기반 문장"으로만 나온다 |
| `backend/.env` | `JWT_SECRET`(32자 이상), `CORS_ALLOW_ORIGINS`에 프런트 주소, `FRONTEND_BASE_URL`(메일 링크 주소) | **프런트 주소를 CORS에 안 넣으면 브라우저에서 가입부터 실패한다**(변수 이름은 `CORS_ALLOW_ORIGINS`) |
| 메일 | `SMTP_HOST`를 비우면 `backend/backups/dev_mail.log`에 링크가 남는다 | 실제 메일 발송까지 보려면 SMTP 설정 |
| 서버 | `uvicorn app.main:app --port 8000` | |

## 2. 프런트 실행(서윤 쪽)

```bash
cd frontend
npm install
VITE_USE_MOCK=false VITE_API_BASE_URL=http://<서버주소>:8000/api npm run dev -- --port 5173
```

PowerShell은 `$env:VITE_USE_MOCK='false'; $env:VITE_API_BASE_URL='http://<서버주소>:8000/api'; npm run dev`.
브라우저 주소와 `CORS_ALLOW_ORIGINS`가 **글자까지 같아야** 한다(`localhost`와 `127.0.0.1`은 다른 주소).

자동 확인 8개(같은 서버에 임시 계정을 만든다):

```bash
VITE_REAL_BACKEND=1 VITE_API_BASE_URL=http://<서버주소>:8000/api npx vitest run src/api/http.integration.test.ts
```

## 3. 같이 볼 것(아직 못 본 것 위주)

각 줄은 "무엇을 하고 → 무엇이 보여야 하는가"다. 이상하면 화면 캡처와 요청 URL을 남긴다.

### 3-1. 실제 LLM·번역 (가짜로는 불가능)

- [ ] 설정에서 언어를 English로 바꾸고 "삼성전자 오늘 왜 올랐어?" -> 답변에 **번역/그 언어로 작성/번역 검증 실패(요약만)** 배지가 상황에 맞게 뜬다.
      "한국어 원문 보기"가 열리고 `report_id`가 없으면 숨는다.
- [ ] 일본어·중국어도 같은 질문. 번역 품질이 읽을 만한가(어색한 금융 용어 메모).
- [ ] 한국어 질문이 아닌 질문(영어)을 보냈을 때 응답과 우리 안내("질문은 한국어가 가장 정확해요")가 어긋나지 않는가.
- [ ] 포트폴리오 AI 진단: `source`가 `llm`이면 "AI 설명(모델명)", 규칙 기반이면 "규칙 기반 설명". 응답 시간이 1분 넘을 때 화면이 안 죽는가.

### 3-2. 실제 뉴스·공시가 든 화면

- [ ] 종목 상세 > 뉴스 카드: 실제 기사 제목·출처·게시 시각(KST)·`related_tickers` 링크. 시황 기사 안내문이 어색하지 않은가.
- [ ] 종목 상세 > 공시 카드: 정정 공시 배지, 접수일(시각 없이 날짜만), DART 링크가 열리는가. 정정만/제외 필터.
- [ ] 수집이 멈춘 상태(`freshness.stale`)의 지연 띠와, 최근 수집 실패(`last_collection.status=failed`)일 때의 "수집 실패" 안내.
- [ ] 일일 브리핑(AI 요약 포함): 직접 뉴스와 간접(업종) 뉴스 상자, 공시 날짜(KST), 지연 띠, "한국어 원문 보기".
- [ ] 사건 반응 카드(뉴스·공시 이후 주가): 표본이 적은 종목의 표시.

### 3-3. 실제 시세·시장 데이터

- [ ] 리서치 홈 "오늘의 시장": 코스피·코스닥 종가와 등락, 상승·하락 막대, 지연일 때 띠. 등락이 `null`인 종목/지수가 "—"로 나오는가.
- [ ] 종목 상세 차트: 20/60/90/180/365거래일 버튼. 상장이 짧은 종목(`available_count` 작음)은 180·365가 꺼지고 이유가 보이는가.
      `missing_trading_days > 0`인 종목의 안내 문구.
- [ ] 장중 실시간 시세(`/realtime-price`)가 3초마다 바뀌고, 장외에는 종가 기준 표시가 나오는가(장이 열린 시각에 확인).
- [ ] 포트폴리오 성과·지수 비교: 실제 체결 뒤 `pending_only`→`ok`로 바뀌는 시점, 지수 비교 기간별(1m~all) 곡선, 데이터 지연 띠.
- [ ] ETF 실질 노출: 실제 KODEX/TIGER 구성종목이 든 ETF를 주문했을 때 기업별 표·겹침·분해 안 함(레버리지) 표시.

### 3-4. 계정·메일(선택)

- [ ] 실제 SMTP를 연결했다면: 이메일 등록 -> 메일이 오는가 -> 링크(`FRONTEND_BASE_URL`)가 우리 화면(`/verify-email`)으로 열리는가.
- [ ] 비밀번호 찾기·재설정 메일 링크, 탈퇴 확인 메일.
- [ ] 구글·네이버 소셜 로그인은 **프런트 화면이 아직 없다**(서버에 공급자 키 설정이 필요하다). 키가 생기면 화면부터 만든다.

### 3-5. 오류·빈 상태(실제 서버에서만 나오는 것)

- [ ] 서버를 끄고 화면을 새로고침: 로그인 확인 실패 안내가 로그인 화면으로 쫓아내지 않고 "다시 시도"를 보여주는가.
- [ ] 429(요청 한도): "n초 뒤 다시"가 화면 언어로 나오는가.
- [ ] 로그아웃 후 다른 계정으로 로그인했을 때 이전 사용자의 데이터가 잠깐도 안 보이는가(캐시 초기화).

## 4. 미리 알아둘 서버 쪽 한도(시험이 막히는 이유 1위)

| 한도 | 기본값 | 증상 |
| --- | --- | --- |
| 가입 | IP당 시간당 10회(`RATE_LIMIT_SIGNUP_PER_HOUR`) | 같은 IP에서 계정을 여러 번 만들면 429 |
| 아이디·비밀번호 찾기 | IP당 분당 5회, 같은 이메일 시간당 3회 | 없는 이메일도 똑같이 센다 |
| 인증 메일 | 사용자당 시간당 5회 | 이메일 등록·재발송 합산 |
| 현재 비밀번호 연속 오류 | 5회 오류 시 5분 잠금 | 이메일 등록·비밀번호 변경·탈퇴가 같은 잠금을 쓴다 |

시험하는 동안 값을 올리거나(`.env`), 서버를 다시 띄우면 메모리 한도가 초기화된다.
