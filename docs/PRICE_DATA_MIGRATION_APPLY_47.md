### 8.2 사후 감사 단계 중단 원인과 처리
- `scripts/audit_close_basis.py`는 `os.environ["DATABASE_URL"]`을 직접 읽는다. `apply47.sh`는 리허설 대상일 때만 이 변수를 내보내고, 개발 DB 대상일 때는 내보내지 않았다(앱은 `.env`에서 읽으므로 앞 단계는 문제없었다). 리허설은 리허설 DB 분기만 탔으므로 이 결함이 드러나지 않았다.
- 멈춘 시점에 데이터를 바꾸는 단계(주식·ETF·지수)는 이미 끝났고 모두 예측과 일치했다. 남은 단계는 사후 감사(READ ONLY 트랜잭션)와 `--dry-run`(쓰기 없음)뿐이었다.
- 처리: `.env`의 `DATABASE_URL`을 내보내는 줄만 더한 재개 스크립트로 5)·6) 단계를 같은 명령으로 돌렸다. 시작할 때 "중단 뒤 변경 없음"을 스냅숏으로 먼저 확인했다. 복구가 필요한 상황이 아니었으므로 복구는 하지 않았다.
- 교훈: 대상별 분기가 있는 스크립트는 실제 대상 분기도 리허설에서 지나가게 해야 한다(예: 실행 대상을 바꾸지 않고 `--dry-run`만 하는 모드).
