# 58차 KRX 연말 거래일 달력 보완과 2027년 갱신 준비 (2026-11-15)

**바꾼 데이터는 `krx_calendar.json`의 2026-12-31 한 날짜뿐이다.** 이 날을 미확정에서 연말 휴장으로 옮겼고, 근거 키 `krx_rule`을 추가했다. 2027년 날짜는 하나도 등록하지 않았고 적용 범위도 늘리지 않았다.
평가 세트 v1·v2, 질문·정답·기준선·임계값, 합성 평가 입력(휴장일 날짜 304행)은 바꾸지 않았다. 개발 DB·프런트엔드·실행 중인 서버는 건드리지 않았다.

## 1. 시작 브랜치와 기준 커밋

| 항목 | 값 |
| --- | --- |
| 브랜치 | `feature/backend`, `origin/feature/backend`와 같은 커밋, 작업 트리 깨끗함 |
| 기준 커밋 | `2d5bf61`(57차) |

## 3. 2026년 연말 공식 일정과 근거

| 날짜 | 판정 | 근거 |
| --- | --- | --- |
| 2026-11-19(목) | 거래일, 10:00~16:30 | 55·56차 그대로 |
| 2026-12-25(금) | 휴장 | 관공서의 공휴일에 관한 규정 제2조 제10호(12월 25일 기독탄신일). KRX 휴장일 규정 "정부 지정 공휴일" |
| 2026-12-30(수) | **2026년 마지막 거래일** | 12-31 휴장의 결과 |
| 2026-12-31(목) | **연말 휴장** | 아래 두 자료 |

12-31의 근거:
1. **KRX 휴장일 규정**([global.krx.co.kr](https://global.krx.co.kr/contents/GLB/06/0602/0602010201/GLB0602010201T1.jsp), 2026-11-15 확인):
   - 규정 문구: "Year-end closure: December 31st (when it's a holiday or a Saturday, one previous business day closest to the December 31st)"
   - 2026-12-31은 목요일이고 공휴일이 아니므로 그날이 연말 휴장일이다.
   - 과거 달력 기록(2023-12-29·2024·2025-12-31)과도 규칙이 맞는다(테스트 `test_year_end_rule_matches_past_years`).
   - 이 페이지에는 연도별 날짜 목록이 없다.
2. **KRX KIND "2026 코스닥시장 공시일정 캘린더"**([PDF](https://kind.krx.co.kr/external/dst/reference/11625/2026%20%EC%BD%94%EC%8A%A4%EB%8B%A5%EC%8B%9C%EC%9E%A5%20%EA%B3%B5%EC%8B%9C%EC%9D%BC%EC%A0%95%20%EC%BA%98%EB%A6%B0%EB%8D%94_vF.pdf), 문서 작성 2025-11-21, 28쪽):
   - 2026년 12월 쪽(25쪽)에 "⁎2026년 증권시장 폐장", "2026년 증권시장 연말휴장", "성탄절" 표시가 있다.
   - 텍스트 추출이라 칸 위치는 남지 않았다. 규정과 합치면 폐장 12-30, 휴장 12-31이다.
   - 읽은 방법: 받은 PDF를 스크래치 폴더에 따로 두고, 스크래치에만 설치한 `pypdf`로 텍스트를 뽑았다. 프로젝트 환경에는 설치하지 않았다.

참고만 한 자료(근거로 쓰지 않음):
- "12월 30일까지 운영, 31일 휴장, 1월 2일 10시 개장" 기사([이지경제](https://www.ezyeconomy.com/news/articleView.html?idxno=228443), 2025-12-18)는 **2025년** 연말 이야기다.
- 2026년 연말 휴장 공지(보통 12월 중순)는 아직 나오지 않았다.

## 4. 12월 25일·30일·31일 처리 결과

| 날짜 | 처리 | 확인 |
| --- | --- | --- |
| 12-25 | 변경 없음(이미 `holiday`, `statute`) | 제품·평가기 모두 `holiday`. 기대 거래일(12-25 12:00) = 12-24 |
| 12-30 | 변경 없음(거래일) | 마지막 거래일. `last_trading_day(12-31)` = `previous_trading_day(12-31)` = 12-30. 12-21~12-31 거래일 7일(12-25 제외) |
| 12-31 | `unconfirmed` → `holidays`(`{"date": "2026-12-31", "name": "연말 휴장", "source": "krx_rule"}`) | 제품·평가기 모두 `holiday`. 중복 없음(검사 테스트). 12-31 12:00·20:00의 기대 거래일 = 12-30 |
| 12-30의 다음 거래일 | 확정하지 않음 | 12-31 휴장, 01-01 신정, 01-02·03 주말, 01-04는 KRX 공지 전이다. 평가기는 2027-01-04에서 `CalendarUnknown`으로 멈춘다. 제품은 01-04를 "열릴 수 있는 날"로 센다(36차 정책, 바꾸지 않음) |

JSON 형식은 기존 휴장일 항목(`date`·`name`·`source`)과 같다. 새 근거 키는 기존 `sources` 사전에 하나를 더한 것이고, 스키마는 바꾸지 않았다. `unconfirmed` 키는 빈 목록으로 남겼다(다음 연말 휴장 공지 전에 다시 쓸 수 있다).

## 7. `CalendarUnknown` 동작 검증

`tests/test_krx_calendar_year_end_58.py`:
- 2027-01-04·02-08·12-30(평일, 범위 밖)에서 아래 다섯 곳이 모두 `CalendarUnknown`을 낸다:
  - `krx_days.is_trading_day`
  - `quality_judges.expected_trading_day`
  - `forecast_check._expected_day24`
  - `run_quality._visible_rows`
  - `metrics._business_days_between`(12-30부터 그 날까지)
- `next_trading_day(2026-12-30)`·`nth_trading_day(2026-12-30, 1)`은 오류를 낸다. 오류가 가리키는 날짜는 2027-01-04이다. 미확정 날짜를 건너뛰어 다른 날을 고르지 않는다.
- 거꾸로 찾는 계산은 확정된 날만 지나면 된다. 예: `last_trading_day(2027-01-03)` = 12-30(01-03 일·01-02 토·01-01 신정·12-31 휴장).
- 2027 설·연말 예상일(02-05·02-08·12-31)도 `unknown`이다. 규칙으로 만들지 않는다.
- 미확정(`unconfirmed`) 동작 자체: 실제 파일에는 미확정일이 없어졌다. 그래서 12-31을 미확정으로 되돌린 합성 달력으로 제품(`unknown`·"(미확정)" 이름)과 평가기(오류 메시지 "미확정 휴장일")를 계속 시험한다.

- 실행 중인 백엔드(PID 28088)는 건드리지 않았다. 그 서버는 달력을 시작할 때 한 번 읽는다. 그래서 이번 12-31 변경도 55·56차 변경처럼 **재시작 뒤에야 반영된다**(재시작은 승인 대기).
  - 12-31까지는 시간이 있지만, 11-19 수능일 때문에 그 전에 재시작이 필요하다.
- 제품 코드 변경: `app/krx_calendar.py` 모듈 설명의 예시 한 줄("예: 2026-12-31" → "예: 공지 전의 연말 휴장일")만 고쳤다. 동작은 바뀌지 않는다.
- 공개 API 필드 변경은 없다. 2026-12-31의 응답 값(기대 거래일·지연)만 바뀐다(8절).

## 12. 2027년 연간 달력 갱신 절차

KRX가 2027년 휴장일(보통 12월 중순, 다음 해 일정과 그해 연말 휴장)을 공식 발표하면 아래 순서로 한다.

1. **공식 공지 확인**:
   - KRX 홈페이지 공지사항 또는 KIND 자료에서 원문을 본다.
   - 증권사 공지는 KRX 공지를 직접 인용한 경우에만 보조 근거로 쓴다.
   - 언론 기사·예상표는 근거로 쓰지 않는다.
2. **날짜·사유 확인**:
   - 휴장일마다 날짜와 사유(설·추석·대체공휴일·선거일·임시공휴일·근로자의 날·연말 휴장)를 확인한다.
   - 정부 공휴일은 관공서의 공휴일에 관한 규정과 공휴일에 관한 법률(대체공휴일) 최신본과 대조한다.
3. **특수 거래시간 확인**: 연초 개장일(예년 10:00 개장), 수능일, 그 밖의 시간 변경을 확인한다. 공지된 것만 `special_sessions`(`open`·`close`)에 넣는다.
4. **달력 반영**(`backend/app/data/krx_calendar.json`):
   - `holidays`: `{"date", "name", "source"}` 형식. `source`는 `krx_notice`(공지) / `statute`(법정 공휴일) / `krx_rule`(규정)이고, `sources`에 URL과 확인 날짜를 적는다.
   - `coverage.end`: **2027년 전체 휴장일이 공지된 뒤에만** 2027-12-31로 늘린다. 범위를 늘리면 범위 안 평일이 모두 거래일이 되므로, 일부만 알 때는 늘리지 않는다.
   - `unconfirmed`: 범위 안이지만 공지 전인 날(예: 그해 연말 휴장 공지 전의 12-31)
   - `version`·`updated`를 바꾼다.
5. **형식 검사**: `pytest tests/test_data_quality_calendar.py tests/test_krx_days_eval_57.py tests/test_krx_calendar_year_end_58.py`. 제품 로더와 평가 로더가 각각 다음을 오류로 잡는다:
   - 중복·주말·범위 밖 휴장일
   - 범위 안에서 빠진 고정 공휴일
   - 날짜·시각 형식, 개장 >= 마감
6. **거래일 계산 회귀**:
   - 55~58차 달력 테스트와 평가기 테스트 전체를 돌린다.
   - 새해 연말·연초 기대값을 이 문서 8절처럼 새 테스트로 추가한다.
   - 제품과 평가기가 모든 날짜에서 같은 상태인지 본다(`test_status_matches_product_calendar_everywhere`의 검사 구간을 새 범위까지 늘린다).
7. **평가 실행**:
   - `run_quality --mode deterministic`, `run_eval --mode offline`
   - v1 실답 1회와 `rescore_routes`(v1·v2)
   - 변경 전 결과와 문항 단위로 비교한다. v2 "1개월=24"는 실행일 고정값이라 경고를 함께 기록한다.
8. **기록**: `docs/DATA_QUALITY_AND_TRADING_CALENDAR.md`의 출처·버전, 변경 보고서(추가한 날짜·근거 URL·확인 날짜·바뀐 판정).
9. **Git·CI**: `feature/backend` 커밋, CI(backend-unit·backend-integration·eval-offline·secret-scan) 확인, 실행 중인 서버 재시작(승인).

일정: 12월 중순 공지 직후, 늦어도 **2026-12-31 전**에 한다. 그 전에는 2027년 평일에서 평가기가 멈춘다(의도된 안전 중단).
- 운영 보고서(`refresh_data --status`)는 그 날들을 `calendar_unknown`으로 표시한다.
- 답변에는 "달력으로 확인할 수 없는 날" 문장이 붙는다.

## 13. 남은 위험과 다음 작업

1. **2026년 연말 KRX 공지 원문**은 아직 나오지 않았다. 규정과 KIND 자료로 등록했다. 공지가 다르면(예: 임시 휴장 추가) 12절대로 고친다.
2. **2027년 달력 미등록**: 12절 일정대로 해야 한다. 늦어지면 2027-01-04부터 평가가 멈추고, 제품 답에 지연 확인 불가 문장이 붙는다.
3. **대체공휴일 확대 개정**(기독탄신일·부처님오신날, 입법예고 기사): 2027 달력에 반영할 때 확인한다. 2026-12-25는 금요일이라 해당 없다.
4. **서버 재시작**(55·56·58차 반영): 승인 대기다. 기한은 11-19 09:00 전이다.
5. **합성 입력의 휴장일 날짜 304행**(57차): 별도 승인과 작업이 필요하다.
6. **v2 "1개월=24" 실행일 고정**: 실행일별 기대값이 필요하면 평가 세트 변경 작업으로 따로 한다.
