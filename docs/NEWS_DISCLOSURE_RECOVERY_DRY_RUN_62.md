   - 뉴스 11만 건은 지금 표의 6배다. 화면 목록·브리핑·리서치 도구의 기사 수가 크게 늘어난다(관련성 낮음 9,672건은 목록에서 빠진다).
   - 그대로 넣을지, 범위를 줄일지 정해야 한다. 방법: 관련 기사만, 종목당 상한, 기간 일부(`--start`·`--tickers`·`--max-pages`).
2. **임베딩 부담**:
   - 저장 뒤 `embed` 단계가 새 기사 11만 건의 임베딩을 만든다(Ollama `bge-m3`, 13434).
   - 61차까지의 단계 기록(2,500건 약 76초)으로 셈하면 약 1시간이다. 그동안 채팅 답변이 느려질 수 있다.
3. **시간이 지나면 수가 바뀐다.** apply는 다시 요청해서 받는다. dry-run 수치와 정확히 같지 않다. 특히 잘린 49종목은 받은 시작이 더 늦어진다.
4. **실행 기록**: apply는 `data_refresh_run` 1행(+ 종료 갱신)과 `data_refresh_log` 2행을 쓴다(14절). 남기지 않으려면 코드 옵션이 필요하다.
5. **잠금**: apply는 `refresh_data`와 같은 advisory lock을 잡는다. 다른 갱신과 동시에 돌리지 않는다.
6. **재실행**: `--state` 파일로 이어서 실행한다. 다시 실행해도 이미 있는 (종목, URL)·접수번호는 건너뛴다.
7. 1,000건 한계를 넘으려면 검색어 분할 같은 새 규칙이 필요하다. 기존 수집 규칙(종목명 검색)과 달라지므로 별도로 정한다.
