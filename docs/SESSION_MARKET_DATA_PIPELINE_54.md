## 2. 세션 일정(캘린더) 구조

| 파일 | 역할 |
| --- | --- |
| `backend/app/data/krx_session_schedule.json` | 일정 데이터. `default`(정규 일정)와 `overrides`(날짜별 전체 일정) |
| `backend/app/session_schedule.py` | 읽기·검증(`parse`), 날짜별 조회(`resolve`), 기존 달력과의 마감 불일치 보고(`calendar_mismatches`) |

일정 하나가 담는 것:
- 시장: `KRX`만. NXT는 넣지 않고, `market`이 KRX가 아니면 파일 자체를 거부한다
- 날짜(변경일)
- 정규 연속매매 창
- 종가 단일가 봉 시각, 지연 창(선택)
- 장후 종가매매 창
- 애프터마켓 창과 대상 자산·시작일
- 변경 사유, 공식 근거 URL(https, 필수)
- 상태: `data_verified`(실제 분봉으로 검증) 또는 `announced`(발표로 등록, 실제 분봉 검증 전)

시각은 모두 분봉 **시작 시각**(KST, 양 끝 포함)이다. 집계 코드에는 세션 시각 상수가 없다(53차의 15:30·16:00 등 상수를 지웠다).

파일을 읽을 때 오류로 거부하는 경우(테스트 14종):
- 근거 없음·https 아님
- 사유 없음
- 알 수 없는 상태
- 주말·휴장일·달력 범위 밖 변경일
- 같은 날짜 두 번
- 세션 겹침·순서 오류(정규장 → 종가 단일가 → 지연 창 → 장후 종가매매 → 애프터마켓)
- 시작 > 끝
- 알 수 없는 자산 구분
- 시각 형식 오류
- NXT 시장

향후 임시 일정: `overrides`에 날짜·시각·대상·사유·근거만 더하면 코드 수정 없이 적용된다(`test_new_special_day_only_needs_a_data_entry`). 근거 없는 일정은 파일 검증에서 거부된다.

## 3. 일반 거래일과 특수 거래일 구분

`session_schedule.resolve(d)`:

| 경우 | 결과 |
| --- | --- |
| 휴장일·주말 | `None, non_trading_day` → 분류 안 함 |
| KRX 달력 범위 밖(2027년 이후) | `None, calendar_unknown` |
| `overrides`에 있음 | 그날 일정(`kind=override`) |

- 거래일 여부는 기존 달력에서, 세션 시각은 세션 일정에서 읽는다.
- 분류 결과에는 쓴 일정(`date·kind·status·label`)이 남는다.
- 두 파일의 마감 시각이 다르면 `calendar_close_mismatch` 표시가 붙는다(16절 1번).

지연 창을 열지 않은 이유:
- 정규 일정의 15:31~15:39 규칙(15:32 지연 체결)은 관찰 35건으로만 확인했다.

- `announced` 일정의 날짜는 분류·검증·미리 보기는 되지만, 적재(`--load`)에는 `--allow-unverified-schedule`이 필요하다.

## 5. 세션별 집계 공식

종목 1개 × 거래일 1개 × 세션 1개 = 행 1개. 세션 안의 봉을 시간순으로 놓고:

| 값 | 공식 |
| --- | --- |
| 시가 | 첫 봉의 시가 |
| 고가 | 봉 고가의 최댓값 |
| 저가 | 봉 저가의 최솟값 |
| 종가 | 마지막 봉의 종가 |
| 거래량 | 봉 거래량의 합 |
| 봉 수, 첫·마지막 봉 시각 | 세는 값, 첫·마지막 봉의 시작 시각 |

- 거래대금은 만들지 않는다(원천에 없음).
- 가격은 원본 JSON의 숫자를 `Decimal`로 읽어 그대로 쓴다(`NUMERIC` 자릿수 제한 없음). 수정주가 ETF의 소수 12자리가 보존된다.
- 집계 전 검증: 아래 중 하나라도 있으면 **그 종목-날짜 전체를 거부**한다. 잘못된 봉만 빼고 나머지를 집계하지 않는다.
  - 시각 형식, 초 ≠ 00
  - 가격 ≤ 0, OHLC 모순
  - 음수·비정수 거래량
  - 중복 시각
  - **원본이 시간순이 아님**(`out_of_order`, 54차 추가. 정렬로 감추지 않음)
  - 거래일 불일치(봉 날짜별로 묶고, 대상 날짜 봉만 그날로 본다)
  - 종목 코드 형식·미등록(`unknown_ticker`)
  - 일정의 어느 창에도 맞지 않는 봉(`unclassified_bars`)
  - 종가 단일가 후보 충돌
  - 정규장 봉 없음
  - 미완성 수집(일정의 마지막 봉 + 11분 전, 정규·수능일 모두 20:10)

## 7. 종가 단일가와 ETF 예외

- **종가 단일가 판정**:
  - 그날 일정의 종가 단일가 봉(정규 15:30, 11-19 16:30)이 있으면 그 봉을 쓴다.
  - 단일가 모양(시가=고가=저가=종가)이어야 한다.
  - 그 봉이 없을 때만, 일정에 지연 창이 있으면 그 안의 단일가 봉 **하나**를 인정한다.
  - 후보가 둘 이상이면 고르지 않고 거부한다(`test_multiple_late_auction_candidates_are_rejected`).
  - 종가 단일가 봉이 있는 날의 지연 창 봉도 거부한다.
  - 공식 종가 일치는 분류에 쓰지 않고, 적재 단계에서 따로 대조한다.
- **장후 종가매매와 분리**: `closing_auction`(봉 1개)과 `post_close`(15:40~15:59 봉들)는 시가·고가·저가·종가·거래량을 따로 계산한다. 가격이 같아도 거래량을 합치지 않는다(`test_closing_auction_and_post_close_are_never_merged`).
- **ETF**:
  - 종가 단일가 체결이 없으면 `closing_auction` 행을 만들지 않고 `no_closing_auction` 표시만 남긴다(실제 7건).
  - ETF는 애프터마켓 대상이 아니다. 16시(11-19는 17시) 이후 봉이 있으면 분류하지 않고 거부한다. 애프터마켓 행을 만들지 않는다.

## 16. 남은 위험

1. **11-19 기존 달력 불일치(개발 서비스 영향, 결정 필요)**
   - 기존 `app/data/krx_calendar.json`에는 11-19 특수 마감이 없어서 기존 서비스가 그날 15:30에 장이 끝났다고 본다. 영향:

     - 장중 판정(`session_is_open`): 브리핑·시장 요약이 15:30~16:30을 장 마감 뒤로 본다.
     - 기대 거래일(`expected_trading_day`): 그 사이 오늘 데이터를 기대해 지연으로 보일 수 있다.

   - **11-19(목) 장 시작 전 결정이 필요하다.** 넣으면 세션 일정과의 불일치 표시도 사라진다(`calendar_mismatches() == []`).
