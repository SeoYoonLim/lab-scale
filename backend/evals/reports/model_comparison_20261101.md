# 모델 비교: llama3.1:8b, qwen3:8b, qwen2.5:7b-instruct (2026-11-01)

**결론: 기본 모델을 바꾸지 않는다(llama3.1:8b 유지).** 두 후보 모두 사전에 고정한 조건을 못 채웠다. 대신 `OLLAMA_CHAT_MODEL`로 바꿀 수 있게 했다.

남은 한계에 대한 답:
- **어색한 한국어와 영어 혼입은 모델 탓이 크다.** 어색한 문장이 llama 13.5%, qwen3 2.7%다. qwen3는 외국어 혼입도 0건이었다.
- **사실 오류는 모델을 바꿔도 해결되지 않았다.** 문장 기준 llama 14.9%, qwen3 12.6%, qwen2.5 19.3%이고, 오류가 있는 답변은 llama 13/23, qwen3 20/25, qwen2.5 17/22로 오히려 후보가 많다.
- **단, 이 비교는 llama에 맞춘 프롬프트로 한 것이다.** 후보는 도구를 건너뛰고 지어낸 답이 많았다(qwen2.5 12/22, qwen3 4/25, llama 0/23). 프롬프트를 후보에 맞추면 달라질 수 있으나 이번에는 공정 비교 규칙상 하지 않았다.

## 하드웨어와 후보 선정

- GPU: NVIDIA GeForce RTX 3050, VRAM 8,192MiB (다른 앱이 약 1,480MiB 사용). RAM 63GB, 디스크 여유 911GB. Ollama 0.40.13.
- 현재 모델 호출: 옵션은 `num_predict`만 있었고 `keep_alive`·`num_ctx`는 없었다(`num_ctx`는 지금도 Ollama 기본값).
- `qwen3:8b`(5.2GB, 도구·생각 지원): 새로 받았다. 8B라 현재 모델과 크기가 비슷하다.
- `qwen2.5:7b-instruct`(4.7GB, 도구 지원): 이미 설치돼 있어 받지 않았다.
- 14b 계열(약 9GB)은 제외했다. VRAM 8GB를 넘어 CPU로 넘치므로 지연 조건 (e)와 동시 적재 조건 (f)를 넘기 어렵다(측정하지 않은 판단).

## 한계와 아직 모르는 것

- **후보는 프롬프트·few-shot 튜닝 없이 비교했다.** 도구 건너뛰기와 지연은 튜닝으로 달라질 수 있다. 이번 결과는 "그대로 바꾸면 나빠진다"이지 "모델이 본질적으로 못하다"가 아니다.
- 사람 판독은 한 명이 모델 이름을 알고 읽었고, 답변 앞부분만 읽었다. 판독 수치는 경향으로만 봐야 한다.
