# 보안 (backend)

2026-10-30 백엔드 전체 점검(읽기 전용 점검 → 높음·중간 보강) 결과와 운영 체크리스트. 대상은 커밋 d93cca5(소셜 로그인 포함)와 그 뒤 보강이다.
API별 상세는 [API.md](API.md), 테스트는 `tests/test_security_*.py`(라우트 전수 인증·위조 JWT·헤더·413·레이트 리밋·탈퇴·로그·인젝션).

## 적용된 통제 (요약)

- **인증**: HS256 고정(alg=none·HS512·다른 키 거부), `sub`·`exp`·`iat`·`tv` 필수(2026-10-30부터 `tv`도 필수), 24시간 만료, 로그아웃·비밀번호 변경·재설정·탈퇴 시 `token_version`으로 모든 기기 토큰 폐기.
  `JWT_SECRET`은 32자(바이트) 미만·`.env.example`의 `<...>` 자리표시면 모든 모드에서 기동 거부, 예시 낱말·반복 문자는 운영(`APP_ENV=production`)에서 거부.
- **비밀번호**: argon2id(t=3, m=64MiB, p=4: OWASP 권장 m=19MiB·t=2 이상), 로그인 성공 시 파라미터가 오래된 해시는 재해시. 8~128자 + 흔한 비밀번호 목록·한 문자 반복 거부 +
  아이디·이메일 앞부분 포함 거부(가입·변경·재설정 공통). 없는 아이디·비밀번호 없는 계정도 더미 해시 검증으로 응답 시간을 맞춘다. 로그인 잠금은 아이디+IP 조합(남의 계정을 다른 IP에서 잠그지 못한다).
- **인가**: 인증 필요 라우트는 전부 `get_current_user`(라우트 분류 테스트가 새 라우트 누락을 막는다). 소유자 범위는 `user_id` 또는 소유자 키 `user:{id}`로만 조회하고, 남의 것과 없는 것은 같은 404.
- **복구·소셜 로그인**: 인증된 이메일로만 복구, 열거 방지(같은 200·같은 본문, 조회는 응답 뒤), 토큰은 SHA-256만 저장·1회용·조건부 UPDATE, 링크·코드는 fragment.
  소셜 로그인은 서명 state + HttpOnly 쿠키(로그인 CSRF 방지), 구글 PKCE·nonce, 양쪽 검증된 이메일만 자동 연결.
- **HTTP**: 보안 헤더(`X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`, `Permissions-Policy` 최소 권한), `/api/auth/*`와 로그인한 요청의 응답은 `Cache-Control: no-store`,
  HSTS는 `SECURITY_HSTS=1`일 때만, 요청 본문 1MB 제한(413), 운영에서 `/docs`·`/redoc`·`/openapi.json` 끔. 500은 고정 문구, `/api/auth/*`의 422는 입력값을 되돌려주지 않는다.
- **남용 방지(메모리 기반)**: 로그인·가입·복구·토큰 제출·소셜 로그인·AI·백테스트·주문 한도 + 모든 GET `/api/*` IP당 분당 600회 + 같은 수신 주소로 보내는 메일 시간당 10통(모든 종류 합산) + 탈퇴 시도 사용자당 시간당 5회.
- **로그**: 앱 접근 로그는 쿼리를 남기지 않고, uvicorn 접근 로그도 필터로 쿼리를 지운다(소셜 로그인 콜백의 code·state 포함). 보안 이벤트는 `app.security` 한 줄(이벤트, user id, 결과, IP /24·/48).
  미처리 예외는 종류와 코드 위치만(예외 메시지에 섞일 수 있는 SQL 파라미터는 남기지 않음). 질문 원문·이메일·토큰·비밀번호는 로그에 남기지 않는다(메일 관련 로그는 수신자 마스킹).
- **개인정보 삭제**: `DELETE /api/auth/me`(회원 탈퇴)가 그 사용자의 모든 데이터를 한 트랜잭션에서 지운다.
- **AI 에이전트**: LLM 도구 8개는 모두 공개 시장 데이터 읽기 전용이고 사용자 식별자를 인자로 받지 않는다. 개인 데이터(채팅 브리핑)는 서버가 요청 사용자로 직접 읽는다.
  답변은 숫자·날짜·대상·기간 검증 뒤 **근거 링크가 아닌 URL이 든 문장을 지운다**(프롬프트 인젝션 피싱 링크 방지).

## 회원 탈퇴의 삭제 범위

`DELETE /api/auth/me`(또는 소셜 계정의 확인 링크)가 한 트랜잭션에서: 소유자 키 `user:{id}`의 `watchlist`, `virtual_account`(→ `holding`, `trade` CASCADE)를 지우고,
`users` 행을 지우면 `research_report`(→ `tool_call_log` CASCADE), `portfolio_diagnosis`, `account_token`, `oauth_identity`가 CASCADE로 지워진다.
WHERE는 그 사용자의 id·소유자 키뿐이라 다른 사용자 행은 건드리지 않는다(테스트가 다른 사용자의 모든 테이블 행 수가 그대로인지 확인한다). 사용자 행이 없어지므로 남은 JWT는 전부 401.
본인 확인: 비밀번호 계정은 현재 비밀번호, 비밀번호 없는 소셜 계정은 인증된 이메일 확인 링크(30분 1회용), 둘 다 없으면 10분 안에 로그인한 토큰 + 아이디 재입력.
**로그(서버 로그 파일)와 DB 백업 파일 속 과거 데이터는 지워지지 않는다**(아래 운영 체크리스트).

## 남은 위험과 완화 계획

- 레이트 리밋·잠금이 메모리 기반: 재시작하면 초기화되고 워커·인스턴스마다 따로 센다. 여러 프로세스로 운영하면 Redis 같은 공유 저장소로 옮긴다.
- 프록시 뒤에서는 모든 요청이 같은 IP로 보인다(X-Forwarded-For는 믿지 않음). 운영 배포 시 신뢰할 프록시만 지정하는 설정이 필요하다.
- 토큰이 24시간 유효하고 localStorage 등 브라우저 저장소에 있으면 XSS에 노출된다(프론트 책임). 짧은 액세스 토큰 + 갱신 토큰은 아직 없다.
- 프롬프트 인젝션: 링크는 막지만, 뉴스 제목 속 숫자와 권유 문구는 막지 못한다(위 표). 답변은 항상 근거(sources)와 면책과 함께 보여야 한다.
- 개인정보 보존 기간 정책 없음: 탈퇴하지 않은 사용자의 질문 원문(research_report)·tool_call_log는 무기한 보관된다. 보존 기한(예: 1년)과 정리 작업이 필요하다.
- pillow 메이저 업그레이드(13.0.0)는 matplotlib 호환을 확인한 뒤 별도로 한다.
- 비밀번호 유출 목록(HIBP 등) 대조는 하지 않는다(외부 요청). 내장 목록은 작다.
- 실제 키로 소셜 로그인을 확인한 적이 없다(API.md "소셜 로그인" 한계).

## 운영 체크리스트

- `.env`는 커밋하지 않는다(`.gitignore`: `.env`, `.env.*`, 예외 `.env.example`). `JWT_SECRET`은 `python -c "import secrets;print(secrets.token_urlsafe(48))"`로 만들고 공유하지 않는다.
  운영은 `APP_ENV=production`(약한 시크릿 거부, API 문서 끔), HTTPS면 `SECURITY_HSTS=1`, `OAUTH_REDIRECT_BASE`는 https 주소.
- **로테이션**: `JWT_SECRET`을 바꾸면 모든 토큰이 무효가 된다(전체 로그아웃). DB를 백업에서 복원하거나 마이그레이션을 내렸다 올린 뒤에는 `token_version`·토큰 사용 기록이 되돌아가므로 `JWT_SECRET`을 바꾼다.
  SMTP·구글·네이버 client secret이 새면 공급자 콘솔에서 재발급하고 `.env`를 바꾼 뒤 재시작한다.
- **백업 파일**: `backend/backups/*.dump`에는 사용자 데이터(계정, 이메일, 질문 원문, 해시)가 들어 있다. 커밋 금지(gitignore), 공유 금지, 필요 없어진 덤프는 지운다. 외부로 옮길 때는 암호화한다.
  `backups/dev_mail.log`에는 유효한 링크가 들어 있다(개발 전용, 공유 금지).
- **로그 보관**: 앱 로그·uvicorn 로그는 쿼리·비밀값을 남기지 않게 했지만 IP(uvicorn)·user id는 남는다. 보관 기한을 정하고(예: 30~90일) 접근을 제한한다.
  `app.security` 이벤트는 계정 이상 징후(연속 login fail, login_locked) 확인에 쓴다.
- **DB 포트**: 개발 DB는 `127.0.0.1`에만 연다(compose). 기본 계정(postgres/postgres)은 로컬 개발 전용이고 운영 DB에는 강한 비밀번호와 네트워크 제한을 쓴다.
- 실행: `uvicorn app.main:app --port 8000 --no-server-header`(서버 종류 헤더를 숨김, 선택).
- 의존성: 주기적으로 `pip-audit -r requirements.txt`를 돌리고 호환되는 패치 버전만 바로 반영한다.
